# Security assessment

## Scope and execution

Record run ID, date, source revision/dirty state, runtime identity, authorized assets,
roles, exclusions, intent, depth, available tools, lifecycle and coverage status.

## Findings

For each finding: ID/title, evidence class, severity and confidence, affected instances,
attacker prerequisites, invariant, ROOT CAUSE, EVIDENCE (baseline/adverse/control),
counterevidence, FIX APPLIED or PROPOSED, HOW TO TEST, and PREVENTION.
Link actual redacted evidence and state executed versus reasoned verification.

## Coverage

List planned surface/risk/technique rows and outcomes. Separate no_issue_found,
ruled_out, not_applicable, needs_follow_up and untested; include reasons and links.

## Remaining work

Name missing tools, credentials, runtime proof, unresolved candidates and unrun checks.
Do not infer full coverage, safety or compliance from a completed run or zero findings.
